## System Overview

This document provides a condensed overview of a legacy COBOL mainframe system consisting of 42 programs that process financial transactions, manage customer accounts, and maintain historical records. The system uses a batch orchestration architecture complemented by online real-time transaction handlers.

**Quick Facts:**
- 42 programs (28 batch, 14 online, 17 utilities)
- 412 business logic paragraphs
- 15 extracted business rules
- 62 data entities with 1,573 fields
- DB2 + VSAM storage

---

## Core Business Functions

1. **Batch Transaction Processing** - Main business logic: validate transactions against account status and credit limits, update master accounts, maintain audit trail
2. **Account Management** - Real-time account inquiry, portfolio management, card status control
3. **History Loading** - Archive historical transactions to DB2 for long-term analysis
4. **Error Handling & Recovery** - Comprehensive error logging and checkpoint-restart capability

---

## Key Business Rules

### Confirmed Rules (Must Enforce)
- Account balance cannot go below zero
- Transaction amount must not exceed customer credit limit  
- Account status must be Active to accept transactions

### High-Confidence Rules (Should Enforce)
- Credit limit enforcement with overdraft handling
- Transaction routing based on type and amount
- Error recovery via checkpoint restart

### Requires SME Review (5 rules)
- Account type validation for transaction types
- Transaction date range validation
- Data integrity checks
- Overdraft policy details
- Reporting thresholds

## Process Flow at a Glance

`
Input Transaction File
    ↓
BCHCTL00 (Batch Orchestrator)
    ↓ FOR EACH TRANSACTION:
RCVPRC00 (Validation) → Check limits, status, amount
    ↓
POSUPDT (Update) → Apply credit/debit to master  
    ↓  
ERRPROC (Error Handler) → Log any issues
    ↓
HISTLD00 (Audit Trail) → Archive to DB2
    ↓  
Output Report File
`

## Architecture Pattern

**Hub-and-Spoke:**
- **Hub:** BCHCTL00 and PRCSEQ00 (orchestrators)
- **Spokes:** Transaction processors, report generators, utilities
- **Shared Infrastructure:** Error handlers, DB2 access, audit logging

**Data Sharing:** Account and Transaction records accessed by 10+ programs each, indicating high data coupling
